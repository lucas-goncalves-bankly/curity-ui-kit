# Core Restore and Partner Portal Multi-Brand Deploy

This runbook explains how to:

1. Restore Identity Server core templates in an environment back to Curity defaults.
2. Deploy Partner Portal multi-brand theme and templates.

It assumes SSH access to the target server.

## Scope and Goal

Use this process when environment files were overwritten directly under core paths and you need to:

- Return non-branded flows to Curity default behavior.
- Keep brand customizations only in overrides and template-areas.

## Prerequisites

- SSH access to the target host.
- A backup strategy for `/opt/idsvr/usr/share`.
- Up-to-date local repository with Identity Server artifacts built:

```bash
npm run build:identity-server
```

- Remote deployment helper script available in this repository:
  - [deploy-remote.sh](deploy-remote.sh)

## Folder Strategy (Target State)

The target state should follow this structure:

- Curity defaults: `/opt/idsvr/usr/share/templates/core`
- Global customizations: `/opt/idsvr/usr/share/templates/overrides`
- Brand-specific customizations: `/opt/idsvr/usr/share/templates/template-areas/partner-portal`
- Assets: `/opt/idsvr/usr/share/webroot/assets`

Do not keep brand-specific files inside `templates/core`.

## Phase 1 - Backup Current Environment

Run from your local machine:

```bash
export HOST=<remote-host>
export USER=<remote-user>
export SHARE_DIR=/opt/idsvr/usr/share
export TS=$(date +%Y%m%d_%H%M%S)

ssh "$USER@$HOST" "mkdir -p $SHARE_DIR/backup_$TS && cp -a $SHARE_DIR/templates $SHARE_DIR/backup_$TS/ && cp -a $SHARE_DIR/messages $SHARE_DIR/backup_$TS/ && cp -a $SHARE_DIR/webroot/assets $SHARE_DIR/backup_$TS/"
```

## Phase 2 - Restore Curity Core Defaults

You have two valid options:

1. Recommended: reinstall or re-extract the same Curity version package and restore only `templates/core` from the clean distribution.
2. If you already have a clean copy of the same version in another server/artifact repository, copy that `templates/core` into this environment.

Example (replace `<clean-core-source>` with your clean source path on the remote host):

```bash
ssh "$USER@$HOST" "rm -rf $SHARE_DIR/templates/core && cp -a <clean-core-source>/templates/core $SHARE_DIR/templates/"
```

After this phase, core should be back to Curity defaults.

## Phase 3 - Remove Legacy Customizations in Wrong Locations

If old custom files were placed in core paths, remove them before applying the new model.

Example check:

```bash
ssh "$USER@$HOST" "find $SHARE_DIR/templates/core -type f | grep -E 'partner-portal|bankly|custom' || true"
```

If any files are found, remove or replace them with default core files.

## Phase 4 - Deploy Partner Portal Multi-Brand Customizations

Use the repository script to sync built artifacts to the remote environment:

```bash
npm run deploy:remote -- --host "$HOST" --user "$USER" --remote-share-dir "$SHARE_DIR"
```

Optional flags:

- Dry run (no changes):

```bash
npm run deploy:remote -- --host "$HOST" --user "$USER" --remote-share-dir "$SHARE_DIR" --dry-run
```

- Delete remote files that do not exist locally in synced folders:

```bash
npm run deploy:remote -- --host "$HOST" --user "$USER" --remote-share-dir "$SHARE_DIR" --delete
```

## Phase 5 - Verify Expected Files in Environment

Run verification commands:

```bash
ssh "$USER@$HOST" "ls -la $SHARE_DIR/templates/template-areas/partner-portal"
ssh "$USER@$HOST" "ls -la $SHARE_DIR/templates/overrides/authenticator/html-form/authenticate/get.vm"
ssh "$USER@$HOST" "ls -la $SHARE_DIR/templates/overrides/authenticator/totp"
ssh "$USER@$HOST" "ls -la $SHARE_DIR/webroot/assets/css/partner-portal-theme.css"
ssh "$USER@$HOST" "ls -la $SHARE_DIR/webroot/assets/images/logo_bankly_preto.svg"
```

## Phase 6 - Restart Curity and Validate Functionally

Restart service (example):

```bash
ssh "$USER@$HOST" "sudo systemctl restart idsvr"
```

Validation checklist:

- A client without template area uses Curity default screens.
- A client with template area `partner-portal` uses partner branding.
- TOTP and html-form pages follow your customized layout in overrides.
- Verification email renders the expected logo for partner-portal.

## Rollback

If needed, restore the backup created in Phase 1:

```bash
ssh "$USER@$HOST" "cp -a $SHARE_DIR/backup_$TS/templates $SHARE_DIR/ && cp -a $SHARE_DIR/backup_$TS/messages $SHARE_DIR/ && cp -a $SHARE_DIR/backup_$TS/assets $SHARE_DIR/webroot/"
```

Then restart Curity.

## Notes

- If your server policy allows SFTP only, upload the same folders preserving structure.
- The theme file currently generated by this repository is:
  - `partner-portal-theme.css`
- If operations require `custom-bankly-theme.css`, rename during upload or adjust setting in:
  - [src/identity-server/templates/template-areas/partner-portal/settings.vm](src/identity-server/templates/template-areas/partner-portal/settings.vm)
